# 동적 라이브러리 빌드

`iiNetwork`은 기본적으로 공유 라이브러리로 빌드한다. 정적 산출물이 필요한
소비자는 `BUILD_SHARED_LIBS=OFF`를 명시할 수 있다. 공유 라이브러리의 공개
CMake 타깃과 헤더 경로는 유지하며, Windows에서는 공개 심볼을 DLL에서
내보내고 iOS에서는 프레임워크로 설치한다. 애플리케이션은 실제 사용하는
공유 라이브러리와 필요한 런타임 의존성을 자체 패키지에 내장해야 한다.
WebAssembly 공유 구성은 사이드 모듈로 생성하며 호스트의 동적 로딩 지원과
해당 대상용 네트워크 의존성이 필요하다.

테스트는 라이브러리 소비 실행 파일의 연결 정보를 검사하며 이 검사를 위해
앱을 실행하지 않는다. 다른 운영체제와 실제 기기의 동작은 해당 환경에서 별도
검증해야 한다.

네트워크 공개 API는 Core 값을 유지한다. 최신 iiJson의 독립 값과는 JSON
직렬화 경계에서 명시적으로 변환하며 기존 입력·출력 제한을 그대로 적용한다.

Emscripten 소비자 설정은 공유 사이드 모듈을 가져오기 전에 CMake의 공유 라이브러리 지원을 활성화한다. 앱의 메인 모듈 컴파일·링크 옵션은 빌더 또는 앱이 지정해야 한다.
